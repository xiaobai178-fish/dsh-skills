# 原理图 ↔ 固件对账（电机驱动板）

> 与 `datasheet-reading` 技能配合：那个技能负责"把图读成事实表"，本文件负责"事实表与固件逐项对账"。

| # | 事实 | 用途 | 固件侧对应 |
|---|---|---|---|
| 1 | 主控型号与封装 | 外设能力、引脚复用 | `.uvprojx` / `device.h` / `#define` |

## 2. 对账方法（差异清单）

```
对账 = 图上事实 vs 固件常量/配置
├─ 一致 → 记录（不报告）
├─ 图上能算但固件无对应 → 高风险（保护缺失/换算错）
└─ 固件有常量但图上找不到依据 → 高风险（历史遗留/多板共用）
```

**典型的高风险差异**：
- 分压比与固件电压系数差 1.5 倍 → 欠压/过压点全部偏移。
- 采样电阻 2 mΩ 但固件按 4 mΩ 换算 → 电流读数翻倍。
- 图上没有硬件过流比较器，但固件等 `FAULT` 引脚 → 保护形同虚设。
- 死区时间 < 驱动芯片要求 → 直通风险（看驱动手册最小值）。

## 3. 读图入口（电机板常用文件）

- `.SchDoc`（Altium 原理图）：需要 `datasheet-reading` 的解析方法。
- `.PCBDOC`/ODB++/`.NET` 网表：网表优先，因为网表才是真实连接。
- PDF 原理图：按页读，先找"功率级页"与"MCU 页"。
- 数据手册 PDF（MOS/IPM/驱动/主控）：查死区、驱动电平、Vref、采样要求。
